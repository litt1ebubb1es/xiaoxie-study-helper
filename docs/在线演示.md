# 在线演示站（部署记录）

**在线地址：http://154.8.173.226:8443/**

只读快照：能看、能点、能做题，不能录音、不能上传、不能改设置。数据是合成课程

## 1. 它是什么

`webdemo/` 是一个**纯静态**站点（`index.html` + `style.css` + `app.js` + `data/demo.json`），
没有构建步骤、没有外部 CDN、没有后端。

数据由 `tools/export_demo_json.py` 在本机用**真实算法**跑出来，再把结果写成 JSON：

| 页面上的东西 | 数据来自哪里 |
|---|---|
| 时间轴的 L / B 曲线、60 秒窗口 | `Engine.analyze_session()` → `AnalysisResult.windows` |
| 回视点（时间、等级、分数、证据、摘录、术语） | `Engine.diagnosis()["knots"]` |
| 「换个讲法」 | `Engine.reword()`（本次 `llm.backend=off`，走 `review.py` 规则版） |
| 回视点位置条 / 跨节根因 / 复习顺序 | `Engine.diagnosis()` 的 `distribution` / `root_causes` / `plan` |
| 小测（题目、选项、正确答案、原文出处） | `Engine.make_quiz()` → `quiz_items` 表 |

重新生成：

```powershell
.\.venv\Scripts\python.exe tools\export_demo_json.py
```

**为什么不在服务器上跑管线**：演示机只有 2 GB 内存，跑不动 numpy/PySide6 那一套；
而且演示数据必须是合成的，不能把用户录音带出去。所以"算在我这，看在你那"。

## 4. 已知限制（都在页面上写明了）

- **HTTP 明文**，不是 HTTPS。地址栏会显示"不安全"。要 HTTPS 得先有域名（国内 443 需备案），
  或者用自签证书（浏览器仍会警告）。
- **重讲是离线规则版**：这次没接模型，页面上标的是「离线规则版」，没有假称模型生成。
- **三节课内容相同**：`seed_demo` 的合成讲解重复种了三节，只为让"跨节关联 / 根因"有数据，
  所以根因表的几行数值一样。真实课堂里它们会分开。
- **只读**：没有录音、上传、设置页。这些能力只存在于 Windows 桌面版。
- **2 GB 内存**是这台机器的上限；换成真后端（FastAPI + 数据库 + 模型代理）前建议升到 4 GB。

### 为什么是这个码率，不是更高

实测这台机器上行 **205 KB/s ≈ 1.64 Mbps**（`curl -r 0-1048575` 取 1 MB 用 5.1 s）：

| 码率 | 99 秒片子 | 播放表现 |
|---|---|---|
| 1.32 Mbps（介绍片实际） | 15.6 MB | 边下边播可行，余量约 20%，开头缓冲十几秒 |
| 2.5 Mbps | 30 MB | 下载快于播放才不卡，这里不满足 → 会持续缓冲 |
| 6 Mbps（1080p60 原码率） | 72 MB | 只能"下完再看" |

所以不是不想给更高画质，是**码率一旦超过上行，播放器会一直追不上**。
要更高画质的两条路写在下面。

### 页面上的交代

每张卡片都写了：体积、时长、「上行 1.6 Mbps、点开要缓冲十几秒、拖进度条也会顿」，
并给一个 `下载这段（xx MB）` 的直链——想一口气看完就先下。
底部还有一句说明：视频是本地真实画面，画面里的网课页面来自 B 站公开课程。

## 8. 动效（这一版新加）

页面是纯静态站，动效全部用 CSS transition/keyframes + 一点原生 JS，没有引入任何库
（服务器只发文件，不跑前端构建）。

### 为什么是这几个，而不是满屏飘

这条产品线只有一个故事：**你在往下听，负荷在涨，到某一刻你掉了，算法把那一刻标出来。**
所以核心动效就是把这个过程演一遍——不是装饰：

1. **时间轴曲线从左往右长出来**（2.4s，easeOutCubic），笔尖带一道扫描光
2. **扫描线到达回看点时，色带才亮起**，标记点跟着弹一下——「算法是在这一刻标记的」
3. 动画结束才开放 hover 查看某 60 秒在讲什么（动画中不响应，避免两者打架）
4. 右上角 **↻ 重播**：想再看一遍生长过程就点，不刷新页面

其余都是很轻的进场，服务于「内容在依次就位」而不是抢注意力：

| 位置 | 动效 |
|---|---|
| 首屏 | 标题、副标、KPI 依次上浮 14px；KPI 数字从 0 滚到真值（08:05 这种不滚，直接显示） |
| 回看点卡片 | 卡片进视口才浮起；分数条从 0 长到 0.86；证据芯片逐个出现（70ms 间隔） |
| 诊断位置条 | 刻度逐根从 0 高度落下（90ms 间隔），高亮刻度脉冲两次 |
| 换讲法 | 切换 tab 时右栏段落依次浮现（90ms 间隔） |
| 小测 | 答对绿光扫过卡片、答错轻微抖动 3px；计分数字 pop 一下 |
| 全局 | 导航按滚动高亮当前区块；右下角回到顶部按钮淡入；卡片 hover 抬 2px |

### 工程约束（写在这里，免得以后改坏）

- **只用 transform / opacity** 做位移与淡入；颜色、阴影只用于小面积短反馈；
  唯一的 width 变化是分数条（88px 的小条，单次），没有 `transition: all`
- 进场一律 `IntersectionObserver` 触发一次即 `unobserve`，不监听滚动逐帧
- `requestAnimationFrame` 循环都有停止条件；**并且都有兜底定时器**：
  帧循环被浏览器节流/中断（后台标签页、省电模式）时直接落到终态。
  这条是实测踩出来的——不带兜底时，图会永久停在一半的曲线上
- 进度值一律钳到 `[0,1]`：时钟回退时 `(now - start)` 可能为负，
  没钳制就会把 `-1`、`-11` 这种数写进 KPI
- 动效时长/缓动收在 CSS 变量里（`--dur-1/2/3`、`--ease`、`--ease-out`）。
  项目原本没有动效规范，这几个值属于临时约定，**需要设计确认后再固化**
- **渐进增强**：`html.js-motion` 是动效的开关。JS 没跑、或系统开了
  「减少动效」→ 不加这个类 → 页面就是完整的静态版，一个字都不会少。
  数字、分数条、曲线在 HTML/画布里本来就是最终值，动画只是重新演一遍
- `prefers-reduced-motion: reduce` 时：不滚动数字、不播放曲线、入场直接到位

### 验证到什么程度

- 已验证：减少动效路径（页面完整可见、数字是真值）、曲线终态完整、色带/标记位置正确、
  导航高亮、窄屏 500px 下卡片/图例/胶囊正常换行、线上 4 个文件 200
- 未验证：动画过程本身的观感。headless Chromium 没有真实帧循环，
  `IntersectionObserver` 与 CSS transition 的推进都不稳定，截图会停在中途。
  **需要人或真实浏览器确认**：滚动时区块是否逐个进场、曲线是否生长、点 ↻ 是否重播
- 顺带修的既有缺陷：根因表之前完全没有样式，5 列在手机上会把整页撑宽；
  现在给了基础表格样式，窄屏把它收进可横向滚动的容器
