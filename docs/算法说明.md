# 算法说明：方案缺口与我的裁决

方案 v1.0 把"做什么"写得很清楚，但**认知负荷与回看点判定有 9 处没写到可实现的粒度**。
这份文档把每一处缺口的裁决、公式、默认值和理由固定下来，代码里的常量与之一一对应
（`dsh_app/config.py::CognitiveSettings`）。

原则：**能改成配置项的一律做成配置项**，并且默认值必须能解释。凡是方案原文有明确数值的
（权重 0.35/0.25/0.15/0.15/0.10、0.6L+0.4B、0.65/0.45、60s/15s、1.5s、0.8/0.7/0.6/0.5/0.3），
一律照抄不动。

---

## 缺口 1：sigmoid 会饱和 —— 加缩放温度 τ

原文（5.2.1）：`L = sigmoid(0.35·TD + 0.25·SS + 0.15·SL + 0.15·SD + 0.10·PS)`

问题：五个特征先做课程内 z-score（均值 0、标准差 1）。加权和 `Σwᵢzᵢ` 的标准差为
`sqrt(0.35²+0.25²+0.15²+0.15²+0.10²) ≈ 0.49`，典型取值落在 ±1.5 之间，而 sigmoid 在
±1.5 处已经接近 0.18 / 0.82，在 ±3 处饱和到 0.047 / 0.953。**结果就是 L 退化成硬阈值**，
方案 5.2.6 想要的"因人而异的连续校准"就没有梯度了。

裁决：

```
L = sigmoid( (Σ wᵢ·zᵢ + b) / τ )      τ = 0.5（可配置），b = 0（可被校准更新）
```

τ=0.5 时输入标准差回到 ≈1，L 在课程内呈现可分辨的梯度。测试 `test_zscore_is_course_relative`
断言 `min(L) < 0.35 且 max(L) > 0.65`，防止以后被人悄悄改回饱和形态。

## 缺口 2：四象限阈值不能用绝对 0.5 —— 改用课程内分位数

原文（5.2.3）：`L > 0.5 且 B > 0.5` 判为显性回看点。

问题：L 的分布中心由 τ 与特征标准化决定，B 的实际取值范围又取决于用户行为密度。
用绝对 0.5，一门"全程都很难"的课会把约一半窗口判成高负荷，与 5.2.3 自己写的
"抑制误报"目标冲突；而一门很平的课可能一个高负荷窗口都没有。

裁决：`l_thr = L 的 P70`，`b_thr = B 的 P70`（`quadrant_percentile`，可配置）。
依据是方案 5.2.1 自己的原则："以本课程自身的分布为基准，而不是用绝对阈值"。

## 缺口 3：行为信号的时间衰减形式没写

原文（5.2.2）："所有事件在时间轴上按窗口累加，取窗口内最大强度并做时间衰减
（越靠近窗口中心权重越高）"。

裁决：

```
B = max_i  wᵢ · exp( -(tᵢ - t_center)² / (2σ²) ),   σ = window_s × 1/3 = 20s
```

- **先衰减再取 max**：如果先取 max 再对窗口整体衰减，窗口边缘的事件会被同一个系数压低，
  与"越靠近中心权重越高"的意图相反。
- 高斯而非线性：连续、可导、尾部收敛，避免窗口边界处 B 跳变导致回看点带抖动。
- 并列时按 `EVENT_PRIORITY` 取（manual_mark 100 > seek_back 60 > replay 55 …）。
  方案 3.2 要求"手动标记权重高于任何自动信号"，但 5.2.2 表格里 seek_back 也能到 1.0，
  两者在极值处并列；强度保持表格原值，**并列时用手动标记说话**。

## 缺口 4：回看点的起止时间与合并规则没定义

窗口是 60s/15s 步长，同一位置会被 4 个窗口覆盖。原文只说 `knots.t_start/t_end` 是回看点区间。

裁决：

1. 标记窗口（`S ≥ 0.45` 且象限为显性/隐性）按时间排序；
2. 相邻标记窗口 `t_start` 差 ≤ 30s 视为同一回看点（`merge_gap_s`）；
3. 回看点区间 = `[首窗口中心 - 25s, 末窗口中心 + 25s]`（`knot_half_width_s`），并夹在
   `[0, 课程时长]` 内，宽度不足 5s 时补齐；
4. 回看点的分数/等级/L/B 取组内 `S` 最大的那个窗口（peak），**依据也从 peak 窗口取**——
   这样"为什么标记这里"解释的就是分数所在的位置，而不是区间的平均位置。

`knot_half_width_s = 25` 的来历：小于 15s 会低于一个步长、回看点带过于碎；大于 30s 会
越过合并间隙，让相邻回看点在时间轴上重叠到无法区分。25s ≈ 半个窗口减去一个步长。

## 缺口 5：术语密度 TD 的"领域术语"没有来源

原文（5.2.1）："窗口内首次出现的领域术语数 ÷ 总词数"；5.2.2 说"领域词表加词性规则"，
但没说词表谁维护、怎么覆盖任意学科。

裁决：三级来源，全离线、确定性：

1. **内置学科词表**：通用 / 数学 / 计算机 / 经济管理 / 物理化学，约 150 条高频术语；
2. **课程内自动 n-gram**：2–5 字、出现 ≥3 次、不含标点、非停用词、且**不是更长候选的子串**
   （只保留极大 n-gram）；
3. **英文/缩写正则**：`\b[A-Za-z][A-Za-z0-9_+\-]{2,}\b`。

"首次出现"按课程内字符偏移计算，再经"字符→时间"映射落到窗口。已知局限：
n-gram 会把常见搭配也抽进来（如"接下来看"），但在 z-score 归一化下只是平移，不影响
窗口间的相对排序；真正需要精确术语表时，用 `data/` 下的词表覆盖即可（预留接口）。

**但 n-gram 不能直接当知识点。** 第一版把 `TermLexicon` 的所有术语都拿去标注知识点，
结果漏洞地图的知识点列出现"注意、条件、这里涉及"这类口语碎片 —— 那是垃圾，不是知识点。
裁决：术语分两级，**只有"可信术语"（学科词表命中 + 英文/缩写）才能当知识点**；
自动 n-gram 只用于 TD 特征计分，不参与 F4 的知识点标注。同时 n-gram 抽取本身加了三道过滤：
首尾虚词、口语词头（注意/这里/我们/首先…）、口语标记包含。去噪后同一份演示数据的
知识点从"注意、这里涉及"变成"定义、必要条件、边界条件、最优解、充分条件"。

## 缺口 6：以"词"还是"字"为计量单位

原文用"总词数""平均分句长度"。中文分词结果不稳定，且会引入额外依赖与版本差异。

裁决：**统一以字为计量单位**。z-score 是尺度无关的，换单位不改变归一化后的判别力；
`SS` 是比值（窗口字速 ÷ 全课平均字速），本身无量纲。分句按标点 + ≥300ms 停顿切分：
`SL` = 窗口内平均分句字数。

## 缺口 7：校准的负样本从哪来

原文（5.2.6）：`wᵢ ← wᵢ + η(y − ŷ)xᵢ`，y 来自"用户是否点开重讲、是否标记已掌握"。

问题：真实使用里绝大多数回看点用户根本不处置。若只等显式反馈，样本永远 < 20 条，
η 永远处于减半状态，校准形同虚设。

裁决：两条来源 + η 调度：

| 来源 | y | 样本权重 |
|---|---|---|
| feedback: confirm_useful / replay_opened | 1 | 1.0 |
| feedback: mastered / not_helpful / dismissed | 0 | 1.0 |
| **硬负样本**：`S ≥ 0.65` 但从未被处置 | 0 | 0.3 |

硬负样本的假设是"重点回看你看见了却什么都不做，多半是它其实不成立"，用 0.3 的权重表达
这个假设的不确定性（等价于承认有 30% 概率它是真回看点）。方案 7.4 的"权重校准过拟合"
风险由 η 调度兜底：`n < 20` 时 η 减半，`n > 100` 时 `η × (100/n)` 逐步衰减。

## 缺口 8：知识点图谱的"前置依赖"边没有生成方法

原文（3.5）要求"按前置依赖排序而非时间顺序"，但 `knowledge_points` 只有节点字段，
没有边表，也没说边从哪来。

裁决（务实版，明确标注为近似）：

1. 回看点 → 知识点的关联：取该回看点窗口文本中命中词典、且出现次数最高的前 3 个术语；
2. 共现边 `co_occur`：同一回看点内的知识点两两连边，权重 1.0；
3. 复习顺序：按 `(回看点分数降序, 时间升序)` 排列，知识点去重后输出——
   **这是"近似依赖序"**：高分回看点通常是被更基础的概念拖住的；真正的 `prerequisite`
   边留待接入生成模型后由 LLM 抽取（表结构已支持 `kind='prerequisite'`）。

明确不做：用随机或纯时间顺序冒充"依赖序"。当前的排序规则写在
`pipeline.Engine.diagnosis()` 里，一眼能看出它是什么。

## 缺口 10：屏幕内容的特征语义（F3）

方案 3.4 只说"截图对回课程"，没说截出来的文字怎么参与负荷计算。

裁决：**屏幕内容不能套用语音的特征语义**。

| 特征 | 语音（老师说了什么） | 屏幕内容（屏幕上写了什么） |
|---|---|---|
| SS | 语速 = 窗口字数 / 说话时长 | 文字密度 = 窗口字数 / 该页停留时长 |
| PS | 长停顿次数（思考、板书） | **长停留次数**（同一页停留 >90 秒） |
| TD/SL/SD | 术语、句长、符号密度 | 同左，语义不变 |

实现要点：

1. 屏幕笔记按"到下一条的间隔"生成时间跨度，这个跨度就是**这页停留了多久**；
2. PS 在屏幕窗口里改为统计"跨度 ≥90s 的段"，因为屏幕内容没有"停顿"这回事，
   连续截图之间不存在语音意义上的停顿；
3. 混合会话（既有音频又有屏幕）**按窗口**判定，屏幕字符占比 ≥40% 才用屏幕语义，
   否则仍按语音说 —— 第一版给整节贴了同一个标签，导致语音窗口也写成"屏幕文字密度高"，
   这是错的，已改；
4. 措辞随之切换（`FEATURE_CN_SCREEN`），保证"为什么标记这里"和证据来源一致。

已知局限：屏幕文字密度受"用户截了几次"直接影响 —— 截得越勤，单页跨度越短。
所以屏幕会话的 PS 只有在"大致等间隔截图"时才有可比性，这一点在界面上没有假装精确。

## 缺口 11：知识库检索的边界（对话用）

用户导入的资料要"参与解释"，就必然要检索。裁决如下：

1. **用 BM25，不用向量**。中文按字二元组切（无需分词），英文按词。理由是端侧装 embedding
   模型和建索引的成本与收益不成比例；代价是**只做字面匹配**，换个说法可能召回不到。
2. **召回不到时的兜底写死在代码里**：把本节回看点的证据文本并进查询再检索一次。
   这是显式兜底，不是假装语义检索——用户能看到的出处仍是真实命中。
3. **出处必须能追溯**：回答下方列出《文件名》第 N 段（相关度）与原文片段；没有命中就不显示
   "依据"，模型只能凭通用知识回答且要自报"这不是你的课程/知识库"。

## 缺口 12：自动抓屏的时机判定

方案 3.4 只写了"截图对回课程"，没说谁来按快门。裁决：**算法决定，不设快捷键**。

- 画面变化率（64×36 灰度、亮度差 >24 记为变化）≥12%；
- 距上次抓取 ≥30 秒；
- 每小时 ≤40 帧；
- 抓完由视觉模型做内容闸门：空文本丢弃。

四个阈值都可调（`AutoCapSettings`）。刻意不做的：不做"模型自己决定要不要抓"的开放判断——
模型每次判断本身就要一次调用，成本比抓一帧更高，而画面差分已经能廉价地滤掉绝大多数帧。

## 缺口 14：本地转写的能力边界

选型结论：云端这个 key 没有转写接口（实测 /audio/transcriptions 返回 404），所以走本地 faster-whisper。

实测数据（157 秒真实中文讲解，纯 CPU int8）：

| 模型 | 体积 | 用时 | 倍速 |
|---|---|---|---|
| small | 464 MB | 40 s | 3.9× |
| medium | 1.5 GB | 54 s | 2.9× |

三个必须在实现里体现的边界：

1. **简繁**：medium 对普通话默认输出繁体，必须用 `initial_prompt` 钉住简体，否则下游的术语匹配
   （BM25 按字面比）会大量漏召回 —— "這是" 和 "这是" 在检索里是两个不同的词。
2. **GPU 失败是运行期才暴露的**：ctranslate2 加载 CUDA 模型不报错，第一次迭代生成器才抛
   `cublas64_12.dll is not found`。所以回落必须覆盖迭代，而且只在**真出错**时才降级
   （不能预先假设 GPU 不可用，那会让有卡的人白跑 CPU）。
3. **速度不等于可用**：转写是课后批处理，45 分钟课 12–16 分钟可接受；
   但如果用户想"听完立刻看结果"，就得靠 GPU 或更小的模型 —— 这条写进界面的提示里，
   不宣称"实时"。

## 缺口 13：画面证据的取法（故事板 vs 抽帧）

方案里没有规定"画面从哪来"。三种取法的取舍：

| 取法 | 帧粒度 | 代价 | 适合 |
|---|---|---|---|
| 界面截图（2.6） | 用户/算法决定 | 0 | 真实上课时的屏幕（含你自己的笔记） |
| **B站故事板** | 约 5 秒一帧、480×270 | 一张雪碧图 ~300 KB | 判断这一页是不是板书/公式/PPT |
| 下载视频 + ffmpeg 抽帧 | 可到 2 fps、原分辨率 | 几十~几百 MB + ffmpeg + 解码 | 读小字、逐帧动作 |

默认用故事板：回看点判定要知道的是"这一段是不是在看推导/公式"，5 秒一帧够用。
明确不足：480×270 看不清小字，也不适合逐帧动作判定。需要更高清的场景应显式降级到"下载指定区间再抽帧"，
而不是假装故事板和原分辨率等价。

另外：故事板的 `index` 字段实测是**秒**（末值 155，视频 157 秒），而文档与部分视频给的是毫秒。
代码里按量级自适应（`_index_seconds`），不硬编码单位 —— 这类"接口和文档不一致"必须当成常态处理。

## 缺口 9：实时标记与"课后批处理"的矛盾

原文 4 处互斥：5.2.1 说 L"在课后批处理阶段计算"，5.5 调度表说"听课中…不做分析"，
但 2.1 把"回退后 3 秒内标记"当作端侧的必要性论据，5.6 又给了 `< 3s` 的指标。

裁决（已获用户确认"听课中可以分析"）：两条通道并存。

- **实时通道**（`LiveAnalyzer`）：每 15s 用最近 3 个窗口的转写重算 L，与刚收到的行为事件
  融合，只在状态栏提示"有疑似回看点"，**不落库、不打断**（ADR-004 仍然有效）。
- **课后通道**：停止录制后做完整分析，落库并生成漏洞地图——这才是交付物。

实时通道的 z-score 用课程前段的运行统计近似，所以它的分数**只做提示、不做结论**。
这是把"3 秒延迟"这个指标诚实地降级成"3 秒级提示"，而不是用课后结果假装实时。

## 附：五个特征的实现细节

| 特征 | 实现 | 窗口无语音时的处理 |
|---|---|---|
| TD | 首次出现术语数 × 100 / 窗口字数 | 记 0，且该窗口标 `valid=False` 不参与 z-score |
| SS | 窗口字速 / 全课平均字速 | 同上 |
| SL | 窗口内分句字数均值 | 同上 |
| SD | 符号/公式/代码标识命中数 × 100 / 窗口字数 | 同上 |
| PS | 窗口内 ≥1.5s 停顿次数 / 窗口分钟数 | 同上 |

无效窗口（字数 < 8 或语音 < 2s）保留在 `windows` 表里但 `valid=False`，
既方便调试，也不会污染 z-score 的均值方差。

## 附：音频指纹（推断"回退/重复播放"）

方案 4.2 表格承认客户端场景"播放行为需推断"。在没有播放器事件时（我们用系统回环，
本来就没有），用声学内容判断：

1. 音频帧长 1 秒，取 12 个频带的对数能量，去均值后归一化 → 12 维指纹；
2. 与 `[now-300s, now-12s]` 内的历史帧做余弦相似度，≥0.985 且连续 2 帧命中 → 判定"这段听过"；
3. 匹配点更早 ≥10s → `seek_back`（payload 带距离）；更近 → `replay`；
4. 20 秒冷却，避免一次回退刷出一串事件。

已验证：8s A + 8s B + 重复 A 能检出 1 个 `seek_back`；12s 白噪声 0 误报
（`tools_smoke.py`）。局限：音乐/掌声/静音的频带分布平坦，容易误判，因此这类事件的
`confidence` 取 0.75，且 B 里 seek_back 的强度下限只有 0.6。

## 缺口 15：方案 5.2.2 的六个行为事件，有几个真能测

方案把回退、重播、停留、降速、失焦暂停、外部检索并列成一张权重表，但没写它们从哪来。
裁决如下：

| 事件 | 是否落地 | 依据 |
|---|---|---|
| `seek_back` / `replay` | 是 | 声学指纹自相似（12 频带对数能量、余弦 ≥0.985、连续 2 帧、回溯窗 12–300 秒、冷却 20 秒） |
| `pause` | 是（新增） | 环回流出现 ≥3 秒数字静音；或设备采样数停止增长 |
| `overstay` | 是（复用） | 静音 ≥20 秒，或同一窗口内事件加停留时长超阈值 |
| `slowdown` | 否 | 需要播放速率；声音侧只能靠变速指纹匹配，误报高，暂不做 |
| `blur_pause` | 否 | 需要窗口焦点信息，不录屏就拿不到 |
| `external_search` | 否 | 同上 |

原则：宁可少标，也不能让行为信号里混进猜的成分——B 一旦虚高，S 就会把正常段落判成回看点。
因此 `pause` 的强度上限只有 0.70（`0.45 + 0.25·min(1, 暂停秒数/60)`），低于 `seek_back` 的 0.6–1.0。

## 缺口 16：回看点不会熄灭 —— 缺的是「掌握度」这一维

前面所有公式算的都是**这一段内容有多难**（L / B / S），没有一条算**这个知识点你会不会**。
后果很具体：漏洞地图上的回看点只会越积越多，永远是同一张照片，没有任何东西会变绿。

补法（借 HKUDS/DeepTutor `learning/mastery.py`）：

```
掌握度 = Σ(wᵢ·cᵢ)/Σwᵢ        w = (0.5, 0.7, 0.85, 0.95, 1.0)  只取最近 5 次
封顶：1 次证据 ≤0.5，2 次 ≤0.8（防蒙对）
门槛：0.9 → 已补上
回看点熄灭：挂在它上面的知识点全部过门槛（不是平均，是全部）
```

三个设计取舍：

1. **从全历史重算，不累加**。每次新增证据都重新跑一遍 `compute_mastery`，规则改了旧数据也能按新口径解释。
2. **定性通过直接 1.0**。「这段我本来就会」是用户下的结论，不是待估参数，不走加权。
3. **没术语就不算解决**。自动 n-gram 会带进口语垃圾，所以知识点只认可信术语（学科词表 / 英文缩写）；
   一个回看点若一个可信术语都没抽到，它永远不算「补上」——宁可留在清单上，也不假装解决。

仍未做的（DeepTutor 有、我们没有）：**遗忘曲线**。真实的复习排程需要
`stability/difficulty/retrievability` 三量与时间衰减（他们用指数遗忘，目标留存 0.9），
我们目前只有「现在会不会」，没有「多久后会忘」。这是下一步。

## 附：知识库为什么要按页切

原来的做法是全文 `chunk_text(600/60)` 硬切，`kb_chunks` 只有 `ord/title/text`。
问题不在检索质量，而在**引用无法回溯**：命中后只能说「第 3 段」，用户回不到原文，
和「补看回看点画面」能定位到某一帧完全不对称。

改法：先按原始结构切「定位块」（PDF 页 / PPT 幻灯片 / DOCX 标题 / MD 标题 / 字幕条目），
**再在每个块内部切 600 字**。这样每块都继承 `page / section / source_ref`，
且**绝不跨页**——跨页的块回答不了「第几页」。

顺带一个坑：短文本过滤门槛（≥8 字）会把幻灯片标题整条丢掉。带定位的块用 `min_chars=2`。

## 缺口 17：证据的质量 —— 自评不算证据

缺口 16 把「掌握度」补上了，但它的输入只有一个：用户点「这个讲明白了」。
那是自评。自评的问题不是不诚实，而是**没有分辨率**：点三次都一样，答错也点得下去。

于是按「一组题 = 一次测量」重做证据链：

```
回看点 → 取这一段的原文 → 出 3 道 4 选 1 → 答 → 对/错写进 kp_attempts(source='quiz')
                                          ↘ 作废（出处查不到）→ 不写
```

三条硬规矩，每条都对应一种失败：

| 规矩 | 挡住什么 |
|---|---|
| 题面 ≥12 字、选项恰好 4 个且去重 | 模型给「以上都对/都不对」这类自相矛盾的题 |
| 每题必须带 `evidence`（支持答案的原句） | 模型凭空编题 |
| `evidence` 必须能在本节原文里查到 | 模型编造页码、引用外部知识 |

第三条的比较用 `evidence_key()`：去掉行号行、空白、连字符后做子串匹配。
归一化是必要的——PDF 转文本会在句中插行号（`"fall short in\n3\ndelivering"`），
断词处补连字符（`"DeepTu-\n4\ntor"`）。这些都不改变"这句话是不是原文"。

**判分不经过模型**：4 选 1 是对/错二值，确定性判分不会漂移。
作废的题保留在界面上并标黄——让人看见"模型编了一道题"，比悄悄丢掉更诚实。

这也解释了为什么"模型判分置信度 <0.8 记 ungraded"这条（借 DeepTutor
`semantic_assessment`）在我们这里用不上：我们不做开放式评分，就不给开放式噪声机会。

## 缺口 18：三处各自兜底 → 一条重试规则

推理模型把隐藏思考的 token 从同一个 `max_tokens` 预算里扣。请求整块 JSON 时，
思考可能先花光预算，**一个字都还没吐**。provider 不报错，只返回空或截断。

我们此前在三处各写了一套：

| 位置 | 旧做法 | 症状 |
|---|---|---|
| `llm.probe` | 有 `reasoning_only` 标记 | 只是把错误文本甩给用户 |
| `screen.parse_vision_reply` | 失败就当纯文本用 | 识别空返回时静默 |
| `review.fallback_outline` | 模型空返回就给提纲 | 降级但不重试 |

现在统一成 `llm.call_with_retry(run, usable)`：

```
第一次：正常问
   ↓ 空返回 / 解析不出 JSON / 缺期望字段
第二次：同一个问题 + 「别推理，直接输出结果」+ max_tokens 放宽 1.5 倍
   ↓ 还不成
才降级（提纲 / 空结果 / 明确报错）
```

`complete_json()` 与 `complete_text()` 都走它，视觉识别也走它。
没配端点时直接返回（`attempts=0`）——重试是给「问到了但没拿到」用的，
不是用来掩盖"根本没配"。

## 缺口 19：索引过期与查询改写 —— 两个静默失效点

**索引签名**。切块参数（`MAX_CHUNK=600 / OVERLAP=60`）和每份资料的块数共同决定检索结果。
用户改了参数却忘了重建，表现是"说不上哪里不对"——没有任何报错，只是结果变差。

做法：导入/重建时把 `{chunk参数, [(doc_id, n_chunks)…]}` 的 sha1 前 12 位记进 `kv['kb_sig']`。
每次打开知识库面板算一次当前签名，不一致就把"重建索引"按钮点亮并写出两段签名。
重建读不回原文件的那份**明确列出来**——静默跳过会让用户以为它还在索引里。

**查询改写 fail-open**。BM25 是字面匹配，「它是什么意思」检索不到任何东西。
现在的顺序是：原查询 →（空）→ 模型改写成关键词 → 再检索。
每一条失败路径都返回原问题：没配端点、超时（5 秒）、抛异常、输出太长、
输出为空。宁可少一次召回，也不能让"模型抽风"变成"你的问题丢了"。
改写只在原查询**完全落空**时才触发，界面上命中一次就不改——改写本身也有跑偏的风险。

## 缺口 20：掌握度会过期 —— 复习排程

缺口 16 回答了"现在会不会"，但没回答"还能记多久"。一个月前补上的知识点和昨天补上的，
在界面上长得一模一样——这是"看起来在学、其实在漏"最常见的形态。

补的不是完整 FSRS/DSR，而是**一维简化**（只留稳定度 S）：

```
留存   R(t, S) = (1 + 19/81 · t/S) ^ (-0.5)      # FSRS 曲线形状
间隔   t_due    = S·(0.9^(1/-0.5) − 1)/(19/81) ≈ S
答对   S' = S · max(1.05, 1 + 0.9(1 − R))        # 越容易想起来涨得越少
答错   S' = max(0.5, 0.35·S)                     # 打回接近最小值，不归零
定性通过（用户说"本来就会"）S' = max(7, 2.5·S)   # 别第二天又来问
```

为什么砍掉 difficulty：单用户单机，多一个参数只多一个没人调的旋钮。
为什么常数用 FSRS 默认值：它让 **S 天时留存正好 90%**，于是 S 可以直接当间隔用，
不需要再引入 target retention 这个自由度。

三个界面决策：

1. **该复习的排最前**。它掌握度还是 100%，按掌握度排序会被压到最底下，
   等于把最该做的事藏起来。
2. **没测过显示「—」而不是 0%**。"没验证"和"忘光了"是两件事，混成一个数字会误导。
3. **下一步只给一件事**，并写出理由（留存掉到 33% / 只有 80% 没过门槛 / 可以开新节）。
   给一堆选项等于把"该干什么"的判断又丢回给用户。

已知不足：同一节里连着答对（elapsed≈0）时按公式涨 0 倍，会被误读成"白答了"，
所以加了 5% 的增长下限。这是工程折中，不是理论结论——真实间隔数据攒够后应当重算。

## 缺口 21：知识点从哪来 —— 元词不是知识点

旧实现的知识点直接取自"术语密度"那套词表，取出来是 `定义 / 必要条件 / 边界条件 / 最优解`。
这不是抽错了词，而是**取错了层**：那套词表的作用是**点火**（出现这些词说明附近在讲概念），
它描述"这是哪种命题"，不描述"这一节教了什么"。而掌握度、小测、复习全挂在知识点上——
知识点是"定义"，后面整条链再准也没有意义，因为没人会说自己"掌握了定义"。

所以分成两层，各管一件事：

| 层 | 输入 | 作用 | 能不能当知识点 |
|---|---|---|---|
| `features.py` 的 `BUILTIN_TERMS` + 后缀 | 元词（定义/定理/必要条件…） | 算术语密度 → 触发回看点 | **不能** |
| `terms.py` | 定义句式 + 术语后缀 + 学科词表（排除元词） | 产出知识点 | 能 |

术语候选要过三道门：

1. **定义句式**（权重最高）：`所谓 X，是指` / `X 是指` / `X 定义为` / `记作 X` / `设 X =`。
   注意方向：中文里 `X 是指 Y` 的术语在**前面**，把"是指"当成"后面跟术语"的触发词，
   就会把定义正文当术语抓走（`样本空间映射到实数轴` 就是这么来的）。
   被定义过的单字也放行——「所谓鞅，是指…」里的「鞅」就是术语；但单字母不行（`X` `F` `P` 是符号）。
2. **术语后缀**（定理/定律/分布/函数/矩阵/不等式/映射…）：只认**左边界干净**的窗口。
   左边界必须是标点/空白/句首/虚词，否则窗口切在词中间，产出 `样本空间映射` `算出来期望`
   `人把条件概率和联合概率` 这类串。另外术语内部不可能有 `的/和/与/及/或/并把`，出现直接判死。
3. **学科词表**（数学/计算机/物理化学/经济管理）：命中 ≥3 个才判定学科，否则算"通用"，
   宁可不用词表也不要猜错学科。

打分 `score = 0.8·log2(1+n) + 证据加成`；只出现一次的默认丢弃，三个例外：
被明确定义过、命中学科词表、带强后缀（`泊松分布`、`切比雪夫不等式` 出现一次也是术语）。

**子串去重优先留短形式**（`样本空间` 压过 `样本空间映射`），但有两个例外：
长的被明确定义过（`随机变量` 不该被截成 `变量`），或长的分数是短的 1.4 倍以上。

模型只做一件事：**提名**。提名的每个术语必须附一句原文证据，`grounded()` 查不到就丢弃并计数；
模型没配、超时、返回空、全被丢弃——任何一条都退回规则路径，并在
`knowledge_points.origin` 写清这次是 `llm` 还是 `rule`。这是"模型输出是证据，不是事务"的落地：
模型可以提议，能不能成立由代码验。

**ASR 文本没有标点。** 真实转写是「呃然后分布函数呢定义为Fx等于PX小于等于x」这种，
定义句式和边界判断都会失灵，第一版在 ASR 文本上抽出来的是 `呃然后分布函数` `个方差`
`Fx等于PX小于等于x`。三条修法：

1. **边界剥除要交替做到不动为止**：先剥掉「呃」才露出「然后」，只做一轮会漏。同理
   「个方差」是先剥量词再判长度——只削 `个/些`，`条`在「条件」前面、`种`在「种类」前面，不能碰。
2. **公式不是术语**：候选里出现 `等于/小于/大于/不等于` 或"中英混排且长度>3"一律判死
   ——`Fx等于PX小于等于x` 是定义正文。`P值`这类短混排仍然放行。
3. **光秃秃一个后缀不算术语**：后缀候选必须比后缀本身更长，否则「呃然后分布」会靠
   「分布」两个字混进来。

改完同一段 ASR 文本和干净文本抽出的是同一组词：
`随机变量 样本空间 分布函数 期望 方差 条件概率 泊松分布 联合概率`。

规则升级后不需要重听音频：`Engine.rebuild_knowledge()` 按现存转写重算，
并顺手 `prune_orphan_points()` 清掉"attempts=0 且没挂任何回看点"的旧知识点。
真实库的迁移走 `tools_migrate_demo.py --apply`（先备份）。

**退役，而不是删除。** 光"清掉 attempts=0 的孤儿"不够：「必要条件」这种词
被旧规则抽出来、你还真测过一次，所以 `attempts>0` 永远清不掉。它在新规则下再没有任何
回看点引用，于是**没法重讲、没法出题**，可它又挡在门槛前面——「下一步」会一直让你去补一个
不存在的东西。这是"沉默的死锁"，比垃圾名词本身更有害。

现在的规则分三种处理：

| 情形 | 处理 | 为什么 |
|---|---|---|
| 没人验证过、也没挂回看点 | 删除（`prune_orphan_points`） | 纯噪声，没有可保留的信息 |
| 有证据、但已无回看点 | **退役**（`retired=1`） | 证据是真的，删了不诚实；但没有回看点就没法教它 |
| 正常 | 照常参与门槛、顺序、复习 | —— |

退役的 `knowledge_points` 记录仍在库里，只是退出 `gate_lock / learning_order / review_queue`
和掌握度表；界面上写一句「N 个已退役（旧规则抽的，没有回看点可重讲）」，
不让用户以为自己的东西凭空消失了。

## 缺口 22：门槛是闸门，不是显示的数字

以前门槛（90%）只是表格里的一列：掌握度 30% 的知识点，界面照样让你"去做题"或"开新节"。
这等于把"该不该往下走"的判断丢回给用户，而那正是这个软件答应要替他做的事。

现在顺序是硬的：

```
没过门槛 & 没重讲过   → replay（重讲，策略由证据定）
没过门槛 & 重讲过     → quiz（重讲不算证据，得有小测）
过门槛 & 留存 < 90%   → quiz（复习）
都干净                → new（开新节）
```

状态机靠回看点已有的 `status` 走：重讲一次记 `explained`，下一步立刻变成"出小测"。
**降级提纲也算"重讲过一遍"**（用户手里有可照着走的三步模板，不该卡在重讲上出不去），
但反馈里单独记 `replay_degraded`，不把降级当成真讲过。

重讲策略不交给模型挑——模型偏爱挑听起来高级的讲法，而眼下缺的往往是最基础那层。
`Engine.forced_strategy()`：

| 证据 | 策略 | 理由 |
|---|---|---|
| attempts = 0 | `补前置` | 还没建立任何联系，先讲它从哪儿来、依赖什么 |
| mastery < 45%（门槛一半） | `类比` | 基础没立住，先用类比把基本形状立住 |
| 45% ≤ mastery < 90% | `分层复述` | 只差最后一点，补齐细节 |
| mastery ≥ 90% | `具体数字走一遍` | 已过门槛，重讲只为加深 |

`reword()` 的取值顺序因此变成：显式传入 > **闸门强制** > `recommend()`（内容/证据推荐）。

## 缺口 23：知识图谱的边要喂学习顺序

边原来只用来画图。现在它决定"先补哪个"，否则"下一步"只能在没过门槛的知识点里按名字排序——
那既不是学习顺序，也不是用户能理解的顺序。

前置的判定用两条，缺一不可：

1. `first_seen_t(a) < first_seen_t(b)`（**严格**小于）。
   之前的实现用了 `<=`，而首次出现时间全是 0 时，每个知识点都成了彼此的前置，
   互相锁死，顺序等于没排。首次出现时间现在按转写段落真实计算（第一次出现那句话的起止时间）。
2. `mastery(a) < 门槛`（前置自己也没补上，才算挡路）。

排序：主键是掌握度（该补的在前），再做一遍插入式修正，把前置挪到依赖它的知识点之前。
每个知识点因此带 `prereqs`（前置是谁）与 `blocked_by`（前置里仍未补上的）。
「下一步」挑的是**没有被未补前置挡住的第一个**，所以先补「随机变量」而不是「方差」。

演示课实测：`随机变量 → 样本空间 → 分布函数 → 连续/期望 → 均值/方差 → 极限…`

## 缺口 24：练习导入 —— 两条出题路，来源必须分开

模型出题受幻觉限制，所以每题都要回查原文（缺口 17）。但老师发的练习册本来就是权威答案，
一份 40 题的练习比模型现编的 3 道有用得多。两条路都留，但**来源分开记**：

| 来源 | 字段 | 答案可信度依据 | 判分 |
|---|---|---|---|
| 模型 | `quiz_items.source='llm'` | 文案必须能在本节原文查到 | 确定性 4 选 1 |
| 导入 | `quiz_items.source='import'` | 文件给的答案即权威 | 同一套确定性判分 |

解析规则（`exercises.py`）：

- **表头别名**：中文/英文/缩写都认（`知识点|考点|kp|term`、`题干|question`、`选项A|option1|a`、`答案|answer|key`）。
  认不出「题干」时按无表头处理（题干在第 1 列、选项在 2–5 列），并明确提示建议用模板。
- **答案列**接受 `A-D`、`1-4`、或选项原文（去前缀后比对）。
- **编码**：utf-8-sig → gb18030 → utf-16 逐个试；分隔符取逗号/制表/分号中出现最多的。
- **错误必须带行号**：答案对不上选项、选项不足 2 个或超过 6 个、一行题也没解析出来，
  都进 `errors`（含 `row_no`）。这一层最不该有的行为是"静默成功 0 条"。
- **知识点名**能精确对上就挂 `kp_id`（答对答错照常写掌握度）；对不上只存名字，
  并在界面上写清是哪几个——不静默创建知识点，因为"没讲过"和"教过但没抽到"是两件事。

模板：`exercises.write_template()` 有 openpyxl 就写 xlsx，否则退回 csv。
`练习模板` 按钮落在 `data/export/练习模板.xlsx`。

## 缺口 25：垃圾知识点会造成"沉默的死锁"

承缺口 21。修完抽取之后，真实库里还剩一个 `必要条件`：它是旧规则抽的、用户点过一次
「我会了」，所以永远不满足"没人验证过"这个删除条件。而它在新规则下没有任何回看点引用它——
`make_quiz` 需要回看点、`reword` 需要回看点，于是它**既没法被重讲、也没法被出题验证**，
但 `gate_lock` 照样把它算成"没过门槛"，「下一步」就一直卡在它身上。

这是比"抽出垃圾词"更隐蔽的故障：界面看起来在工作，给出的建议却永远无法执行。
判据很简单——**一个知识点如果没有回看点，那它在这个软件里就不存在"教"的可能**。

处置见缺口 21 的三行表：删除 / 退役 / 正常。核心取舍是"证据不删，但退出决策"：
`retired=1` 让它保留在库里（历史证据、复习曲线都还在），同时不参与
`gate_lock / learning_order / review_queue / next_action`。
配套的 `count_retired_points()` 由界面读出来明说，避免用户以为自己见过的词凭空消失。

## 缺口 26：网页视频"自动抓"的判据与迟滞

方案里写的是"录屏 + 转写"，默认用户会点开始录制。但实际用起来最先失效的就是这一步：
打开网页、点播放、忘了点录制。所以需要"看网页视频自动抓"。

**为什么不走插件。** B 站有字幕接口、YouTube 有 API，插件那套在这些站点上很舒服；
但网课的主战场是学堂在线、中国大学 MOOC、超星、智慧树、学校自建平台——它们既没有字幕接口，
也不欢迎第三方插件，改版一次就全废。所以判据放在**操作系统层**：系统回环（WASAPI loopback）
不关心声音从哪来，浏览器、播放器、会议软件都一样。

**判据：浏览器进程有没有音频会话在 Active。** 用 `IAudioSessionManager2` 枚举会话
（pycaw），`chrome/msedge/firefox/brave/qqbrowser/360se/…` 命中且 `state==1` 就算正在放。
系统级判断，所以天然跨站点。

三个必须加的迟滞，否则会得到一堆垃圾会话：

| 参数 | 默认 | 不这么做会怎样 |
|---|---|---|
| `start_after_s` | 2.5 | 点开就关的广告页、误点，各留下一个 0 秒会话 |
| `stop_after_s` | 25 | 课中间暂停、缓冲 10 秒，一节课被切成三四段 |
| 电平复核 | RMS<0.005 连续 `stop_after_s` | 会话"赖着 Active"（流开着、页面静音），录下整夜空气 |

电平复核是实测发现的：机器上放完一段音频后，该进程的会话仍然是 `state=1`。
所以停录条件是**会话不活跃 且 电平安静**，而不是单看会话状态。
反过来，会话短暂消失但电平还有声（切 tab、播放器重载）时继续录——
判据的优先级是"电平 > 会话"，因为电平才是真正录进去的东西。

**会话归到哪门课**：按**站点**（`哔哩哔哩·网课`），不按标题。标题每集不同，
按标题归会让一学期的课散成几十门。节名取页面标题并剥掉浏览器后缀
（`标题 - Google Chrome` / `标题 - Microsoft​ Edge`）。

**已知边界（明说）**：

1. 只有声音。画面证据要靠 3.10 的抽帧，而抽帧要求有视频文件或屏幕采集；
   纯浏览器播放现在只有音频证据，覆盖度那栏会写"只有声音，没有画面"。
2. 音频会话是"进程级"的：同一个浏览器里如果还开着别的出声页面（另一个视频、
   音乐站），会被一起录进去。要更细只能做浏览器扩展拿 tab 级 stream id，
   那就回到插件路线了，暂时不做。
3. 会话名（`DisplayName`）在 Chromium 系里常为空，所以课程名只能靠窗口标题猜站点；
   标题拿不到时退化成 `网页视频（Edge）`。

对应实现：`dsh_app/webvideo.py`（状态机 + 标题/站点解析）、`Engine.start_web_capture/`
`stop_web_capture`（落库 + 记 `web_capture_stop` 事件）、界面工具条的勾选框。
时序全部用注入的假探针测（29 条用例），不需要在机器上真放视频。
